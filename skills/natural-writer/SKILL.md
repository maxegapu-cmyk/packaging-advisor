# 自然写作助手

目标:写出清楚、有料、读起来像人写的文字,并且让它更容易被更多人看到。事实只来自用户和可以查到的来源,不替用户编。

第一次用,先看一眼 `references/example.md` 里的完整示范,就知道每一步大概做到什么程度。

## 先判断是哪种活

| 用户要的 | 怎么走 |
| --- | --- |
| 从零写 | 完整走下面七步 |
| 想写得更火 | 完整走七步,第 3、5、6 步重点用 `references/viral.md` |
| 改稿 | 先读懂原稿想说什么,从第 5 步开始改,标题和开头一起重新看 |
| 只要标题或开头 | 直接按 `references/viral.md` 第二、三节,给备选并推荐一个 |
| 只去 AI 腔 | 只做第 6 步的语言检查,内容一个字不加 |

## 七步

### 1. 问清四件事(只问缺的)

1. 写给谁看?他们已经知道什么,还不知道什么?
2. 读完以后,希望读者想什么、做什么?
3. 手上有哪些素材:事实、数据、经历、例子、引用?
4. 发在哪里,要什么形式、多长、什么语气?文体按 `references/genres.md` 跟用户确认,比如观点文、教程、随笔、介绍、盘点、口播稿。

用户说"你看着办"时,把你的假设写成一行放在初稿前面,方便他一眼纠正。

### 2. 一句话中心

用一句话说清这篇要讲什么。长文先把这句给用户确认,再往下写。后面每一段都要回答同一个问题:它在帮这句话吗?

### 3. 选角度

按 `references/viral.md` 第一节,检查题目"够不够大、够不够新"。给用户两三个角度,每个附一句理由,推荐其中一个。

### 4. 选结构

从 `references/structures.md` 里挑两种合适的结构,各附一句理由,推荐一种。

### 5. 写标题、开头和初稿

- **标题**:按 `references/viral.md` 第二节写五到八个备选,至少换三种写法,推荐一个。正文兑现不了的话,不写进标题。
- **开头**:从五种起法里选一种。头几句之内,让读者知道读下去能得到什么。
- **正文**:一段只讲一件事。能用具体细节,就不用形容词。每隔几段给点新东西。长句短句交替着用。手艺细节见 `references/craft.md`:怎么把抽象写具体、怎么选例子、句子和段落怎么处理。
- **结尾**:落在一句能带走的话、一个具体行动,或者一个读者真心想回答的问题上。
- **事实**:用户没给、你也查不到来源的数据、引用、经历,一律写成 `[待补:需要一个具体例子]`,不编一个看起来很像的。

### 6. 自查三遍

**内容**
- 删掉不服务中心句的段落和句子。
- 每个事实都能说出来源;说不出来的,改得保守一些,或者标成待补。
- 重复的、绕弯的、只有道理没有例子的段落,缩短或者补上例子。
- 按 `references/craft.md` 第五节,先改大再改小,并试着删掉两成字数。

**传播**
- 对照 `references/viral.md` 第五节:这篇至少占了一两个"让人想转发的理由"吗?

**语言**
- 对照 `references/ai-patterns-zh.md` 逐层检查,从最刺眼的地方改起。
- 在心里念一遍,念着别扭的地方就改。
- 改完再核一次:有没有加进原来没有的事实,有没有丢掉原来的意思。

**打个分**:标题、开头、信息量、情绪和共鸣、语言自然,五项各打 1 到 5 分。哪项低于 3 分,先改哪项。

### 7. 交付

依次给出:
1. 推荐的标题,以及两三个备选;
2. 正文;
3. 五项评分,每项一句话说明;
4. 待补清单:还缺的事实、没核实的说法,没有就不列。

## 跟着用户的口气走

用户给了自己写过的文字,就先看他的句子长短、常用词、语气和标点习惯,改写时跟着这些走。他的习惯优先于本 skill 的任何建议。

没给样本时,按文体来:观点、随笔、个人经历,保留作者的口气;说明、教程、报告,写得平实清楚。

## 不要动的地方

引文、专有名词、作者故意保留的口头禅和方言,还有那些只有真人才写得出的细节,都保持原样。
