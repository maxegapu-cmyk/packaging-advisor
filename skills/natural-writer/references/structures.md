# 常用结构

挑结构只看两件事:手上的素材是什么样的,读者读完要得到什么。下面是最常用的六种。

| 结构 | 适合 | 怎么开头 | 怎么收尾 |
| --- | --- | --- | --- |
| **问题 → 原因 → 办法** | 教程、经验、解决方案 | 直接点出读者正在遇到的问题 | 给一个能马上去做的第一步 |
| **故事 → 转折 → 道理** | 观点文、人物、个人经历 | 从一个具体时刻或场景切进去 | 道理只说一次,而且要从故事里自然长出来 |
| **结论先行 → 论据** | 汇报、评论、给忙人看的文字 | 第一句就给结论 | 说明这个结论意味着什么、接下来怎么办 |
| **对比** | 选择、评测、前后变化 | 先摆出两边最大的那个差别 | 说清楚什么情况下选哪边 |
| **清单** | 方法合集、盘点、注意事项 | 一句话说明这份清单能帮读者做什么 | 只点出其中最要紧的一条,不要再列一遍 |
| **时间线** | 事件经过、人物经历、项目复盘 | 从最关键的那个节点开始,再倒回去讲 | 落到现在,或者落到它留下的影响上 |

## 几条通用的经验

- **一篇只用一种主结构。** 中间可以插一小段故事,或者一组对比,但主线不要换。
- **清单类每条都要带例子。** 只有观点、没有例子的清单,读者很快就没耐心了。
- **故事要有具体的人、时间、地点。** "有个朋友"不如"去年冬天,我的同事小王"。用户没给细节,就留待补,不要编。
- **标题要让人知道读完能得到什么。** 可以具体到数字、场景、对象,但正文兑现不了的话,不要写进标题。
